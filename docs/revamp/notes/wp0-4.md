## Deviations from the spec and why

Where §14 gives no serde shape, these are choices. Each one is pinned by a golden fixture.

1. **Tagging conventions.**
   - Unit enums are snake_case strings. This includes `FrameKind`, which never appears in JSON on the wire because the kind travels as the binary byte.
   - Data enums are internally tagged: `kind` for `Scope`, `FolderPhase` and `GateState`; `state` for `MountState` and `StoreHealth`; `event` for `StatusEvent`; `cmd` for `FolderCmd`.
   - `ObjectOutcome`, `PageStatus` and `ProcessEvent` are externally tagged (`"completed"`, `{"progressed":{…}}`). This keeps `ProcessEvent::Line(StartupLine)` exactly as specified, even though `StartupLine` is untagged.
2. **`MountState` is `#[serde(flatten)]`ed into `MountStatus`.** A status therefore reads `{"intent","path","state":"attach_failed","error",…}`, which is what the WP2.1 qualification expects (`mount.state=attach_failed`).
3. **`ErrorWire.retry_after_ms` and the WP4.1 `token` fields are omitted when `None`.** They are still `#[serde(default)]`. The reason is that §6.1's example Ready line, `mount_error` and `worker.json` then match byte for byte. All other `Option` fields serialize as `null`.
4. **`ReadyLine` IPC-v3 fields are `#[serde(default)]`.** These are `instance`, `pid`, `address`, `version` and `ipc`. A 6298d0b Ready line therefore parses with `ipc == 0`, and WP1.2 rejects it with `WORKER_IPC_MISMATCH` instead of failing to parse.
5. **`PublishedSummary.tip` is a plain `FeedTip`**, as §6.1 specifies, with `#[serde(default)]`. Its `epoch` is `""` until WP2.5.
6. **Types that carry a `paired_sync::SyncRoute` have no `PartialEq`**, because `SyncRoute` has none (see CCR-WP0.4-1). The affected types are `Feed{Offer,Exchange,Apply}Request` and the worker `objects.*` headers.
7. **Additions that §14 does not list.** They are additive helpers, and some freeze plan constants that other packages need:
   - `timing`, `deadlines`, `ops`, `limits` and `policy` constant modules, including every timing value quoted in §3, §4, §6 and §7;
   - `CallError::code` and `Display`/`Error`;
   - `ErrorWire::{new, coded, from_error, into_anyhow}`;
   - `FatalLine::{new, from_error, to_wire}`;
   - `GateState::{kind, allows_attach}` and `FolderPhase::lifecycle`;
   - `StatusExtras`, `HeartbeatEcho`, `Limits`;
   - the `Request`/`Response`/`Chunk`/`Progress`/`Cancel` frame headers;
   - `ConnOptions::for_role`;
   - the `OnChunk` alias, used because clippy's `type_complexity` rejected the inline `&mut dyn FnMut` type. The signature is unchanged.
8. **`WriteItem`, `WriteResult` and `ReportAction` live in `model::protocol::objects`.** WP3.2 lists them under its own *Provides*, but they are fields of the frozen worker-op headers. WP3.2 should `pub use` them rather than redefine them.
9. **`lock_or_exit` logs the generic code `LOCK_POISONED`** (fatal level) after the hook and before `exit(70)`. WP1.4's `lock_engine` hook emits `ENGINE_POISONED`, as §14 WP1.4 specifies. `LOCK_POISONED` and `LOCK_HOLD_EXCEEDED` (the debug log for `Tracked`) are listed as Transient-default codes; they are log codes only.
10. **`session::frame` API.** §14 lists no frame-codec signatures, so WP0.4 defined `Frame`, `FrameLimits`, `FrameError`, `encode` and `decode` as stubs. WP1.9 owns that file and may extend it.
11. **`HEARTBEAT.echo`** is `Option<HeartbeatEcho{seq, at_ms, held_ms}>`. The `held_ms` field makes the RTT exact even though heartbeats are sent only after 5 s of idleness.
12. **Test tolerances.**
    - The "wakes ≤ 10 ms" check for `Snapshot::wait_newer` and `Notify::wait` asserts that the p95 of 20 wake-ups is at most 10 ms and the maximum is at most 250 ms. This leaves room for scheduler noise while the suite runs in parallel. The measured values are well under 1 ms.
    - The `Cancel::sleep` check asserts that every one of 5 samples is at most 50 ms.
    - Golden comparisons normalize CRLF to LF, because `core.autocrlf=true` checks the fixtures out with CRLF.
13. **The code-literal grep** (§8) uses the spec regex `"[A-Z][A-Z_]{3,}`, extended over trailing digits so that `CONFIG_VERSION_2_REQUIRED` counts as one code. It skips `TKFS_*` environment-variable names and an explicit `NOT_CODES` list in the test: SQL keywords, `COMPUTERNAME`, and message substrings that error mappers match (`PERMISSION`, `UNSUPPORTED`, `INVALID`, `DUPLICATE`, `UNIQUE`).

No existing test was changed.

## CCRs filed

- **CCR-WP0.4-1 — `paired_sync::SyncRoute` should derive `PartialEq, Eq`.**
  - Owner of the file: WP1.6 in Wave 1.
  - Reason: the frozen route-carrying IPC and objects types cannot derive `PartialEq`, so tests must compare serialized JSON.
  - Adapter: those types derive only `Clone, Debug, Serialize, Deserialize`. The golden test checks them through re-serialization (`golden` instead of `golden_eq`).
- **CCR-WP0.4-2 — `pairing_code::Verifier` should get a redacting `Debug` and `PartialEq`.**
  - Owner of the file: WP1.10 in Wave 1.
  - Reason: the derived `Debug` prints `hash`, which is HMAC-key-equivalent to the pairing code (§11.15, invariant 21).
  - Adapter: `CatalogSnapshot` and `CatalogCmd` have hand-written `Debug` impls that redact the verifier, and `PeerRecord`/`CodeAuth` redact the code. `CatalogSnapshot` has no `PartialEq`.
- **CCR-WP0.4-3 (process, for every integrator) — new error-code literals must be registered.** `tests/contracts.rs` fails on any new `"SCREAMING_CODE` literal in `src/` that is neither in the §8 table nor in `errors::TRANSIENT_DEFAULT_CODES`, and both lists are frozen.
  - Codes the plan already names for later waves are pre-registered: `NOT_IMPLEMENTED`, `UNSUPPORTED_OPERATION`, `BINARY_OPS_REQUIRE_SESSION`, `ORCHESTRATOR_STOPPING`, `STOP_FOLDER_BEFORE_CONFIGURING`, `WORKER_LIMIT` and `TOO_MANY_SESSIONS`.
  - A package that introduces another code files a CCR, and the integrator adds the code to one of the two lists.

## Known limitations

- **Session stubs.** The session layer is stubs only: `Conn` cannot be constructed until WP1.9, and `dial`/`accept`/`CodeAuth::key` return `NOT_IMPLEMENTED` until WP1.10.
- **Rate-limit summaries.** `util::log` writes a `suppressed N` summary when the next event of that code arrives after the window, or when `flush_suppressed` is called. There is no timer thread; WP4.2 owns `log.rs` and adds rotation.
- **Fault configuration timing.** `util::fault` reads the environment once, on first use. In-process tests use `fault::configure`; daemon and worker processes inherit the variables at spawn.
- **Wall-clock thresholds.** The ≤ 10 ms and ≤ 50 ms checks are wall-clock measurements. They use a p95 over 20 samples, or 5 samples each within the limit, to stay stable while the suite runs in parallel.
