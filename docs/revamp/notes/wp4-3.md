## Deviations from the spec, and why

1. **`tests/docs_cli.rs` checks more than "`tkfs <cmd> --help` succeeds".**
   `--help` succeeds for many wrong lines (`tkfs manage stop X --bogus --help`
   prints help), so the test also checks the subcommand path word by word, the
   options each line uses, and that no command of the binary is undocumented.
   This is what "all `manage` commands" in the CLI row of the task needs to
   stay true.
2. **The previous release's validation records were removed from
   `docs/VALIDATION.md`** (they remain in git history, and their findings are
   in `docs/revamp/ROOT_CAUSES.md`). They described the replaced design's
   pages, lanes and timeouts in the present tense, which the review checklist
   forbids, and their measurements are of the previous release.
3. **The review checklist ("no 15 s timeouts as current behaviour")** is read
   as the previous release's 15 s peer socket timeout. Two current 15 s waits
   are documented because they are real: a read of a file whose bytes have
   not arrived waits up to 15 s before `CONTENT_UNAVAILABLE` (`mount.rs`,
   `runtime::prepare_content`), and `manage stop` waits up to about 13 s
   (`manage::STOP_REPLY_WAIT`; `limits::API_STOP_WAIT` is 15 s). The previous
   release's timeout is mentioned only in the stuck-replica runbook, as past
   behaviour. "List polling" is read as the previous desktop's 5 s refresh;
   the control lane's `catalog.list{since}` every 2 s (answered `unchanged`
   in O(1)) is current and documented as such.
4. **The docs describe this base, not the end of Wave 4.** WP4.1, WP4.2, WP4.4
   and WP4.5 run in parallel; the passages they change are listed below for
   WP4.INT instead of being guessed.
5. **The upgrade runbook for the Docker example uses Docker commands that
   were not executed here** (`docker compose exec`, `docker update
   --restart`, `docker compose up -d`, `docker compose stop -t`): no Docker
   engine runs on this machine. The behaviour they rely on was checked in the
   code (the old daemon's shutdown action, the compose file's
   `restart: unless-stopped` and `exec ./tkfs start`, the new daemon's SIGTERM
   handling).

## Known limitations

- The desktop manual checklist was not run in this package (no code changed;
  WP3.4 ran it). The README's desktop texts come from `ui_model.rs` and its
  tests, not from screenshots.
- The Docker steps of the upgrade runbook were not executed (deviation 5).
- `docs_cli` checks commands and options, not prose: a wrong sentence about a
  correct command is caught only by review.
- The README's timing figures are the development machine's (16-core desktop,
  NVMe); a small server will be slower, mostly in activation and fsync-bound
  transfers.
