## Summary

### 1. CCR-WP3.3-2: the interim bulk path is gone

- **Dialer** (`objects.rs`): the per-key fallback to the Wave 2 interim path
  (worker `published-bulk-offer` → peer `objects.exchange` → worker
  `published-bulk-apply`) is removed with everything that served it:
  `run_bulk_lane_with`, `bulk_exchange`, `BulkOptions`, `BulkOutcome`,
  `fits`, `page_lane`, `worker_ops`, `WORKER_DEADLINE`, `INTERIM_RECHECK`,
  `LaneOptions::interim`, `LaneStats::interim_exchanges`, the lane's
  `modes`/`InterimState`, `RoundEnd::Interim`, `PushError::Interim`,
  `is_unsupported`. `run_bulk_lane` (its frozen signature is pinned by
  `seam_stubs`) runs objects v3 only.
- **Acceptor** (`inbound_objects.rs`): `objects.exchange` is no longer
  routed; like any other unknown `objects.*` op it is answered
  `UNSUPPORTED_OPERATION` before any worker call (`exchange`,
  `completed_parts`, `parse_reply`, `fit_page` removed).
- **What a peer or worker without objects v3 gets now**: nothing special.
  Every peer of protocol 3 serves objects v3 (older peers fail closed at the
  handshake, `PEER_NEEDS_UPGRADE`), and a worker is this build. A local
  worker without loopback sessions (an adopted worker of an older build)
  fails its key with `UNSUPPORTED_OPERATION` (Transient: backed off by
  class, 1 s → 60 s); at the acceptor it reads as a folder that is starting
  (`REMOTE_WORKER_STARTING`, a waiting answer for the dialer's scheduler).
  `objects_v3_lanes::a_peer_without_objects_v3_fails_its_key_without_an_interim_exchange`.
- The worker's `published-bulk-*` ops stay: they are the legacy v6
  in-process replica API kept as a test surface (§11 decision 11;
  `bulk_lanes`, `availability_index`, `support::node` use them); nothing on
  the network calls them any more.
- **Tests rewritten** (§14.5a task 1 says to rewrite them; each kept its
  property on the path that runs now):

  | Interim test (removed) | Objects v3 test (in `objects_v3_lanes` unless said) |
  |---|---|
  | `meta_scheduler::interim_bulk_pages_are_routed` | `every_shared_repository_runs_on_the_lane_with_its_own_route`: both directions of every shared repository on the lane, each with its own route and the lane's spec, under the lane's lease ids at both workers; a paused repository is `Paused` with no worker call; a repository only the peer holds has no key |
  | `meta_scheduler::a_failing_bulk_repository_never_stalls_the_others` | `a_failing_repository_never_stalls_the_others_on_its_lane` (a local worker whose wants fail `OBJECT_IO_ERROR`) |
  | `meta_scheduler::a_key_reset_during_a_bulk_exchange_drops_the_stale_inventory` | `a_replica_change_moves_the_key_to_the_new_route`: objects v3 caches no inventory; what a reset must drop is the lane's per-repository state (lease-id hints, the peer's content counters, `LaneRun::forget`); the object completes from the new replica, the later wants carry its route, no failure is counted |
  | `meta_scheduler::large_bulk_replies_stream_and_oversize_pages_fail_only_their_key` | no page exists any more; streaming of large objects and the per-key isolation are covered by `both_directions_complete_with_per_object_results` (3 MiB objects), `at_most_16_mib_in_flight_per_lane` and the failing-repository test above |
  | `objects_v3_lanes::a_peer_without_objects_v3_gets_the_interim_path` | `a_peer_without_objects_v3_fails_its_key_without_an_interim_exchange` |
  | `inbound_v3::objects_exchange_serves_the_interim_bulk_path` | `inbound_v3::objects_exchange_is_not_served` (refused `UNSUPPORTED_OPERATION`, no worker call, no exchange in the status, the session usable) |
  | `inbound_v3::role_violations_and_route_violations_keep_their_codes` (its `objects.exchange` lane checks) | the same test checks `BULK_LANE_MISMATCH` with `objects.wants` and `objects.pull` (wrong index, wrong count), and that `objects.exchange` is refused |
  | `inbound_v3::paused_and_starting_folders_answer_without_a_worker` (its paused page) | the same test, with an `objects.wants` (`FOLDER_SYNC_PAUSED`) |
  | `inbound_v3::route_binding_uses_the_authenticated_installation` (its bulk half) | the bulk half moved to `inbound_routes_name_the_authenticated_installation` (two authenticated dialers; the acceptor's worker sees each one's installation, its own replica and the request's sender, and the dialer lane's push lease, whatever else the header claims); the `meta.exchange` half stays in `inbound_v3` |

### 2. CCR-WP3.3-4: a source that cannot serve an object gives its lease up

The CCR asked for `WantHeader.exclude` **or** an explicit release. Both are
added, at the worker, and the daemon's own handoff table (WP3.3's adapter)
is removed.

- **Protocol** (`model::protocol::objects`, additive): `ops::RELEASE`
  (`objects.release`), `ReleaseHeader{route, session, hashes}`,
  `ReleaseReply{released}`, `WantRequest{#[serde(flatten)] header:
  WantHeader, #[serde(default)] exclude}` and `MAX_RELEASE_ITEMS` (256).
  `WantHeader` is unchanged (struct literals in other packages' tests keep
  compiling); a worker that reads the plain header ignores `exclude`.
- **Worker** (`objects_rpc.rs`): `objects.want` leaves the excluded hashes
  out of its list and ends this session's leases on them; `objects.release`
  ends the leases `session` holds on `hashes`. Neither touches another
  session's lease, and neither applies the stall backoff of a lapse (the
  orchestrator keeps its own per-source backoff). Lists over 256 are
  `INVALID_REQUEST`; routes are checked as for every op.
- **Dialer** (`objects.rs`): a want excludes the objects in their
  per-object backoff for this source (`blocked_objects`, longest-blocked
  first, at most 256); one the worker returns anyway is released at once.
  At the end of a round, an object that failed for this source is released
  (it is in its backoff now), and when the round failed or stopped (session
  lost, peer or local error, lane stopping) every unfinished object of the
  round is released; a round that merely reached its cap keeps its leases
  and continues them under the same ids. While the daemon stops, nothing is
  released (an adopted worker's leases are continued by the restarted lanes
  under the same ids, or lapse).
- **Acceptor** (`inbound_objects.rs`): an object offered to a dialer and
  not sent (its push ended normally without a byte of it, did not list it,
  or no push came before the next `objects.wants`) backs off for that dialer
  (5 s → 5 min, as before) and its lease ends: the unpushed ones lead the
  exclusion list of that dialer's next want, the rest are released after
  the push. An object of the offer that failed here, and every object of a
  push that failed or that the dialer abandoned, is released too.
- **Removed**: the handoff table (`Handoff`, `Claim`, `handoff_*`,
  `Renewal`, `CLAIM_TTL`, the lane run's claimant, the acceptor's
  per-object offer leases). Every lease is now one session's own; the worker
  is the only arbiter, and a transfer never writes under another session's
  lease.
- **Effect** (two-source scenarios, both sides): the object moves to the
  other source within the round that learned the first source cannot serve
  it, with the first source's lane still running, and without the lapse
  (60 s) plus stall backoff (60 s) the real worker would otherwise impose.
  `a_source_that_cannot_serve_hands_its_push_lease_on` and
  `…_pull_lease_on` run in 0.61 s and 0.66 s each, setup and a 1.5 MiB
  transfer included (debug; bound 30 s, the lease is 60 s), the two
  "holder goes away" tests in 1.97 s and 1.72 s (8 MiB, a session reset
  in between), and they assert the release itself (the worker's release
  log, the exclusion list).

### 3. CCR-WP3.3-1: bulk exchange slots 4 vs the `PEER_CALLS = 2` adapter

Measured (below, *Measurements*, M5): with 4 exchange slots per bulk session
at the acceptor and 4 peer calls per lane, a lane that pulls and pushes at
once through 50 ms / 20 MiB/s downloads at 0.97 of the link instead of
0.80 (the push no longer leaves the pull pipeline one call), uploads at
0.775 instead of 0.80, so both directions together move 9 % more; on
loopback (memory workers) the two are within noise (452–473 against
415–456 MiB/s both ways). **4 measures better.** The acceptor's slot count
is `inbound.rs` (WP4.1's): filed as CCR-WP4.5-2, to be applied together
with `objects::PEER_CALLS = 4` (this package's constant, kept at 2 until
then: a dialer making 4 calls to an acceptor of 2 slots would be refused
`BUSY`). The measurement used a scratch copy with the two-line change; no
WP4.1 file was changed in this branch.

### 4. CCR-WP3.2-1: `fetch_verified` quarantines through the store

`runtime::content::fetch_verified` (now `pub`, for tests) re-verifies under
the object's install lock and renames corrupt bytes aside there, as before;
then, **with the install lock released**, it records the quarantine through
the engine's store (`Store::quarantine_renamed`, new, `core/objects.rs`):
the legacy `object_errors` row, availability `CORRUPT` (with the corrupt
file's length) and the `CORRUPT_OBJECT` backoff (`want_objects` ignores it,
so the repairing download is not delayed), in one savepoint and without
renaming anything (a file at the path now is a copy installed since the
rename, never the corrupt one: nothing is recorded when one is already
there, and the rows are healed to what the filesystem shows if one appears
during the recording). The lock order is the one WP3.INT asked to settle:
the engine lock is never taken under an install lock (the legacy part
receiver takes install locks under the engine lock). `Store::quarantine`
shares the rows (`record_quarantine`). The download is still queued by
`request_object` (unreferenced objects still answer `UNREFERENCED_OBJECT`
as before). `objects_v3_worker::a_verified_read_quarantines_corrupt_bytes_through_the_store`.

### 5. CCR-WP3.2-3: the objects state belongs to the worker context

`WorkerCtx::inflight_objects` (frozen field, CCR applied here; `ctx.rs` is
owned by this package for it) is now `Mutex<ObjectsState>`: `leases`, the
lease `holders` (source of each lease), the per-source backoffs
(`source_backoff`) and the durable-progress signal (`progress:
Arc<ProgressSignal>`), which were process-wide statics keyed by the store
root (`PROGRESS`, `SOURCE_BACKOFF`, `LEASE_HOLDERS`). The three
constructions in other packages' files (`worker/mod.rs`, `tests/feed_v7.rs`,
`tests/seam_stubs.rs`) build the field with `Mutex::default()` /
`Mutex::new(Default::default())`, so they compile unchanged. One lock now
guards all of it (the former order `inflight_objects` → `LEASE_HOLDERS` →
`SOURCE_BACKOFF` collapses; ordered-part waits take the signal's own mutex
and then the state's, as before). `objects_v3_worker` reads leases as
`.leases` (eight accesses; three `get(..).is_none()` became
`!contains_key(..)` for clippy).
`objects_state_belongs_to_its_worker_context`.

### 6. CCR-WP3.INT-5: socket buffers only where they help; control latency

- **Loopback only** (`session/io.rs`, `SocketTuning`, `socket_tuning`): on
  Windows the fixed 4 MiB `SO_RCVBUF` and the adaptive `SO_SNDBUF` are set
  only on a session socket whose peer is this machine's loopback (IPv4,
  IPv6, IPv4-mapped). Any other socket (a LAN, a WAN, a TLS proxy on another
  host) keeps the system's receive-window autotuning and dynamic send
  buffering (both are turned off by setting the option: a fixed 4 MiB
  window carries at most 4 MiB per round trip, 40 MiB/s at 100 ms; and the
  adaptive rule's 50 ms horizon sized a Wi-Fi LAN socket's send buffer to
  100 ms of data ahead of every control frame). Linux is unchanged
  (`TCP_NOTSENT_LOWAT` on every socket, its own autotuning).
- **Loopback send buffer horizon** (`SendBuffer::for_loopback`,
  `LOOPBACK_SEND_HORIZON_MS` = 10): a loopback socket's buffer is sized for
  two 10 ms horizons of data at its drain rate, whatever the session's
  round trip. A session to a TLS proxy or a link emulator on this machine
  measures the far link's round trip, and the rule sized the socket for two
  of those (or 100 ms when none was measured yet: during a saturating
  transfer no heartbeat is sent), i.e. 100–200 ms of data queued ahead of
  every control frame; the proxy's own buffers cover the far link. On
  loopback at GiB/s it still reaches the 4 MiB cap. `SendBuffer::new` (the
  round-trip rule `w3_integration::the_send_buffer_follows_the_drain_rate`
  pins) is unchanged.
- Measured before and after (M1–M6 below): control-session latency under a
  saturated bulk lane p99 52.4–53.5 ms (the floor is < 100 ms; idle 51 ms);
  a ping on the saturated bulk session itself p50 289–301 → 126–127 ms,
  p99 314–326 → 140–141 ms; link utilisation 0.96–0.97 → 0.97–0.98;
  both directions at once 0.70/0.67 → 0.80/0.80; loopback session
  throughput unchanged (every build 3.0–4.1 GiB/s down, 1.9–2.9 GiB/s
  up).

## Deviations from the spec, and why

1. **The handoff table is removed, not complemented** (task 2 asked for
   `exclude` or a release so a source hands an object on without waiting
   for lease expiry). With both at the worker, the table (WP3.3's adapter,
   which wrote under another session's lease) had nothing left to do; its
   WP3.3 note says WP3.INT "may delete it once the worker excludes and
   releases". Its unit test `orchestrator::objects::tests::the_handoff_table_keeps_no_unmovable_item`
   is removed with it (it tested a private function of the table). The
   behaviour it guarded (an object of unknown size handed on after partial
   progress keeps a size another source can move) is still covered end to
   end by `an_object_of_unknown_size_is_handed_on_after_partial_progress` and
   `…_pushed_in_part_is_handed_on`: the worker now reports the size its
   first write took, and no table keeps a stale one.
2. **Changed assertions of the handoff tests** (task 2 changes the mechanism
   they encoded; each test's behaviour, delivery from the second source
   well inside the 60 s lease with the first source's lane still running,
   is asserted unchanged):
   - `a_source_that_cannot_serve_hands_its_push_lease_on`: Y is written
     under C's own lease (was A1's lease, the handoff); new: B released
     A1's lease (the worker's release log) and A1 no longer holds it; the
     sync point "A1 was offered Y" reads the worker's want log instead of
     sampling the lease (the lease now lasts only until the end of A1's
     round).
   - `a_source_that_cannot_serve_hands_its_pull_lease_on`: X is written
     under the lane to C's own lease ids (was the lane to B's); new: the
     lane to B gave X up and its wants exclude X (was: still leased to it).
   - `a_holder_that_goes_away_hands_the_pulled_object_on`: C's writes are
     under C's lease ids and E's under E's (were all under B's); new: C's
     failed round gave X up.
   - `a_holder_that_goes_away_hands_the_pushed_object_on`: the writes of Y
     are under C's and then E's push leases (were all under A1's); new: B
     released A1's lease (not served) and C's (abandoned).
   - `an_object_of_unknown_size_pushed_in_part_is_handed_on`: after A1's
     rounds Y is no longer leased (was: leased to A1), and A1's wants
     excluded it; the writes are under C's and E's leases (were A1's).
   - `both_directions_complete_with_per_object_results`: "no interim
     exchange" is asserted from the recorded exchanges (every one is a pull
     or a push) instead of the removed `interim_exchanges` counter.
   - The FakeWorker of `objects_v3_lanes` implements `exclude` and
     `objects.release` as the worker does, and records its want and
     release calls.
   - `a_failed_worker_call_fails_the_push_not_its_objects` waits (10 s)
     for the dialer's record of its failed push instead of reading it at
     once after the acceptor's record (in WSL it read before the dialer had
     received the acceptor's error; the assertion is unchanged).
   - `a_holder_that_goes_away_hands_the_pulled_object_on`: "what C wrote
     of X is under C's lease ids" allows that C wrote nothing before its
     reset (the WP3.3 assertion allowed it too; an intermediate version of
     this package required a write, which WSL's timing broke).
3. **`objects_v3_worker`'s lease accesses** read `ObjectsState::leases`
   (eight expressions; CCR-WP3.2-3 changed the field's type); no assertion
   changed in meaning.
4. **`inbound_v3` keeps no objects v3 route test of its own**: its fake
   folders have no worker endpoint, so a v3 request stops at
   `REMOTE_WORKER_STARTING` before a worker call; the bulk half of its route
   test moved to `objects_v3_lanes` (real loopback fake workers), see
   item 1's table.
5. **The latency floor is judged on the control session** (lane 0, its own
   connection), as "control-frame latency under a saturated bulk lane"
   reads; the saturated bulk session's own ping is recorded too (M2). On a
   real bottleneck link (a router or a TLS proxy queue shared by both
   connections) the control session's latency also depends on that queue,
   which neither the FaultProxy (per-connection queues with shared pacing)
   nor this package controls; see *Known limitations*.
6. **The acceptance FaultProxy scenario uses memory workers** (M1): with
   disk workers this machine's shared disk, not the data plane, decided the
   result (0.41–0.97 for every build). The disk variant is kept and
   recorded (`qual_wp4_5_large_object_rtt50_20mib_disk`).
7. **`PEER_CALLS` stays 2** although 4 measured better (task 3 says to keep
   the better setting): the acceptor's half is WP4.1's file
   (CCR-WP4.5-2).

  documentation and bounds only). *Requested:* now that the interim path is

  (`ops::OBJECTS_EXCHANGE` itself can stay as a reserved name, as in that

## Known limitations

- **No real WAN in the loop** (see *Measurements*): the WAN-facing socket
  change is reasoned from the platform's documented behaviour and measured
  only on a short non-loopback path (M6); the FaultProxy cannot show a
  long-round-trip socket.
- **The fsync-bound tiny-object floors** (`objects_worker_tiny_10k`,
  `e2e_tiny_files_10k`) fail on this machine as it is now, for the base and
  for this package alike (*Qualification*): its C: drive ran full during
  the work. They need a run on a disk with free space (the coordinator's
  qualification).
- **`a_saturating_push_does_not_delay_pulls_on_a_slow_uplink` in WSL** went
  over its 12 s bound once in four runs of its binary (48 tests at once);
  it passes alone, and on Windows. The Linux socket path (`TCP_NOTSENT_LOWAT`,
  no `SO_SNDBUF`) is unchanged by this package; WP3.INT recorded the same
  test's Linux sensitivity.
- **The WSL distribution failed for a while** during this package (every
  binary answered I/O errors, a read-only `/tmp`, while the C: drive was
  full) and came back without this package restarting it; the WSL results
  above were taken after.
- **Control frames on a saturated bulk session** still wait behind what the
  path queues: 126 ms through the emulator (50 ms of its own queue plus its
  50 ms round trip); on a real link behind a TLS proxy, the proxy's and the
  bottleneck's buffers add what they hold. A sender-side limit on
  in-flight bulk data (a delay-based window) would bound that; it is not in
  this package.
- **`PEER_CALLS` = 2** until CCR-WP4.5-2 lands (M3).
- **A source's backoffs at the acceptor** are not reset when that dialer's
  content grows (unchanged from WP3.INT: the acceptor does not see the
  dialer's counters).
- **Release on a failed round** gives up every unfinished object of the
  round, also when the failure was the peer's for one request only; the
  lane finds them again in its next want (at their durable offsets) unless
  another source took them meanwhile, which is the point.
